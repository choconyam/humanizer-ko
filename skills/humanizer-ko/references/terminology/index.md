# 한국어 용어 안내

직역에서 온 오역이 의심되거나, 아직 정해지지 않은 전문용어를 고르거나, 번역하거나, 바로잡거나, 설명해야 할 때 이 파일을 읽는다. 맞다고 알려진 용어는 그대로 둔다. 반복해서 쓰였다는 사실만으로 맞는 용어라고 볼 수는 없다.

## 옮기기 전에 용어부터 정한다

사용자가 명시한 용어집이나 요구한 스타일을 우선한다. 그런 지시가 없으면 먼저 원문의 정의로 개념을 확인한다. 그다음 대상 분야의 표준이나 전문 문헌, 프로토콜, 제품 문서를 보고 그 분야와 독자에게 맞는 용례를 고른다. 원문의 정의로 뜻은 확인할 수 있지만, 거기에 붙은 한국어 이름이 자연스럽다는 증거는 되지 않는다. 업체 웹페이지의 번역본 하나만으로는 한국어에서 흔히 쓰는 말이라고 할 수 없다.

단어 하나하나가 아니라 개념을 옮긴다. 용어가 개념을 잘못 나타내거나, 다른 전문적인 뜻과 겹치거나, 관련 분야의 용례와 어긋나면 직역어인지 의심한다. 낯설거나 영어에서 왔다는 점만으로는 바꿀 이유가 되지 않는다. 개념과 바꿀 말 모두 근거가 있을 때만 일반 본문을 고친다. 바탕이 되는 사실, 측정값, 방법, 한계는 그대로 둔다.

## 고치거나 불확실성을 드러낸다

- **개념과 대응어가 확인됨:** 분야에서 실제로 쓰는 한국어·음차·영어 표현으로 고친다. 올바른 기존 영어를 억지로 한국어로 바꾸지 않는다. 사용자 지정 용어집은 우선하며, 일반 본문에 같은 오역이 반복되어도 검토한다.
- **음차와 직역 구분:** 사용자가 해당 전환을 명시적으로 요청하지 않았다면 `드롭릿`을 `Droplet`으로 바꾸거나 그 반대로 바꾸지 않는다. 같은 개념의 음차↔영어 전환은 용어 교정이 아니며, 분야 용례나 아래 병기 형식을 이유로 이 제한을 우회하지 않는다. 단어별 직역어는 개념이 같아도 분야 용례와 어긋나는 근거가 있으면 K7로 다듬을 수 있다. 올바른 음차에는 확인 표시도 붙이지 않는다.
- **원어는 확인됐지만 한국어 용례가 불확실함:** 첫 등장에 `English term(한국어 설명·용어 확인 필요)`로 쓴다. 설명도 확신하기 어렵다면 `English term(원문: 기존 표현·용어 확인 필요)`로 원문과 제안을 구분한다. 다음 등장에서는 원어를 일관되게 쓰며, 검토 요청에는 필요한 변경 이유도 알린다.
- **원어나 개념도 불확실함:** 원문 표현을 보존하고 바로 뒤에 `[용어 확인 필요]`를 붙인다. 한국어 표현을 역번역해 영어를 만들어 내거나 뜻이 다른 전문용어를 추측하지 않는다. 문서 목적상 표시를 붙일 수 없으면 짧은 용어 메모에 남긴다.
- **보호 대상:** 코드, API·스키마 필드, 식별자, 제품명, 직접 인용, 승인된 문구, 청구항·계약 문언, 명시적 사용자 용어집은 몰래 바꾸지 않는다. 문제가 의심되면 해당 부분 밖의 메모에서만 확인 대상으로 알린다.

찾아봐야 할 때는 풀리지 않은 개념을 직접 다루는 공신력 있는 기관 자료나 현업 자료 한 곳을 확인하고, 필요하면 영어 정의와 비교한다. 같은 용어가 다시 나오면 그 판단을 그대로 쓴다. 구할 수 있는 근거로도 정해지지 않으면 끝없이 찾지 말고 불확실성 표시 형식을 쓴다. 분야별 안내를 모두 읽거나, 모든 용어를 찾아보거나, 이미 정해진 표현에 두 언어를 병기하지 않는다.

## 빠른 대응표

흔히 뜻이 겹치는 용어는 이 표로 고른다. 이 표와 원문으로 선택이 정해지면 여기서 멈춘다.

| 영어 용어 | 문맥 | 한국어 용례 |
|---|---|---|
| `endpoint` | 임상시험 / API | 평가변수 / 엔드포인트 |
| `claim` | 특허 / 주장 / 보험 | 청구항 / 주장 / 청구·보험금 청구 |
| `cell` | 배터리 / 생물학 | 셀·전지 / 세포 |
| `substrate` | 재료 / 생화학 | 기판 / 기질 |
| `feature` | 머신러닝 / 제품 UI | 특성·피처 / 기능 |
| `validation` | 모델이나 데이터 / 제약 GMP | 검증 / 밸리데이션 |
| `interest` | 대출 / 소유 / 관계 | 이자 / 지분 / 이해관계 |

## 분야별 안내는 풀리지 않은 세부 사항이 있을 때만 읽는다

빠른 대응표로 용어가 정해지지 않거나, 분야별 용례와 상태를 다루는 규칙이 중요할 때만 맞는 안내를 읽는다.

| 분야 | 읽을 안내 |
|---|---|
| 재료, 화학, 증착, 전자공학, 배터리 | [과학·재료](science-materials.md) |
| 소프트웨어, API, 데이터, AI, 머신러닝 | [소프트웨어·머신러닝](software-ml.md) |
| 의학, 임상 연구, 생명공학, 제약 | [의료·바이오](medical-biotech.md) |
| 법률, 규제, 규정 준수, 공공 정책 | [법률·정책](legal-policy.md) |
| 금융, 회계, 투자, 보험 | [금융·회계](finance-accounting.md) |

대응표로 이미 정해진 여러 분야의 용어 목록이라면 분야별 안내를 모두 읽지 않는다. 풀리지 않은 세부 사항 때문에 정말 필요할 때만 두 개 이상 읽는다. 맞는 안내가 없을 때 확신이 서지 않으면 원문의 용어를 그대로 둔다.

## 분야 공통 안전장치

- 원문에서 뜻을 구별하지 않는 한, 한 개념에는 한 용어만 쓴다.
- `한국어 용어(English term)` 형식은 독자나 검증에 도움이 될 때만 첫 등장에 쓴다. 영어를 앞에 쓰는 위의 불확실성 표시 형식은 정확한 원어는 알지만 한국어 대응어가 정해지지 않았을 때만 쓴다.
- 현업에서 보통 영어를 쓰면 영어를 그대로 둔다.
- API 이름, 코드 기호, 모델명이나 제품명, 표준 식별자, 경로, 명령어, 인용 키는 절대 번역하지 않는다.
- 상태와 범위를 보존한다. 용어를 다듬다가 주장을 더 강하게 만들어서는 안 된다.
- 최신 용어, 논란이 있는 용어, 규제 대상 용어, 위험이 큰 용어는 찾아볼 수 있으면 관련된 공신력 있는 자료 한 곳에서 확인한다. 자리 잡은 용어를 유지하려는 이유만으로 검색하지 않는다.
